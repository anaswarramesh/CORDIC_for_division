# CORDIC_for_division

A Doubly pipelined CORDIC architecture for division

---

## Overview

This project designs and simulates a **doubly pipelined CORDIC architecture** for
real-time fixed-point division.  The implementation uses **linear CORDIC in
vectoring mode** (m = 0) to compute:

```
quotient = dividend / divisor
```

A new division can be started on **every rising clock edge**; results emerge with a
pipeline latency of **N + 1 = 17 clock cycles** (N = 16 CORDIC iterations plus one
input-capture stage).

### What "doubly pipelined" means

Two independent sets of pipeline registers exist in the datapath:

| Stage set | Purpose |
|-----------|---------|
| **Stage 0** (input registers) | Samples `dividend` / `divisor` from the external bus; decouples the I/O from the CORDIC datapath |
| **Stages 1 … N** (CORDIC registers) | Each implements one CORDIC iteration; results propagate through N registers at full clock rate |

This separation gives the synthesiser freedom to optimise each half independently,
enabling higher clock frequencies compared to a single-stage monolithic design.

---

## Algorithm

Linear CORDIC, vectoring mode (drives y → 0):

```
Initial:    x[0] = divisor,   y[0] = dividend,   z[0] = 0

For i = 0 … N-1:
    d[i]     = −sign(y[i])    (+1 if y < 0,  −1 if y ≥ 0)
    x[i+1]   = x[i]
    y[i+1]   = y[i] + d[i] · x[i] · 2^{−i}
    z[i+1]   = z[i] − d[i] · 2^{−i}

Result:     z[N] ≈ dividend / divisor
```

**Convergence constraint:** `|dividend / divisor| < 2 · (1 − 2^{−N}) ≈ 2` for N = 16.

**Fixed-point format:** Q16.16 (32-bit signed two's complement, 16 integer bits +
16 fractional bits; value = raw_integer / 65536).

## Quick start

### Requirements

- [Icarus Verilog](https://steveicarus.github.io/iverilog/) (`iverilog` / `vvp`)
- Python 3 (standard library only)

### Build, simulate and verify

```bash
make          # compile → simulate → Python verification (all-in-one)
```

Individual targets:

```bash
make compile  # Verilog compilation only
make sim      # RTL simulation → produces sim_results.csv + .vcd
make verify   # Python reference + comparison with RTL output
make clean    # remove generated artefacts
```

## Test cases (real-time example: normalised signal/sensor ratios)

| # | Dividend | Divisor | Exact quotient | CORDIC result | \|error\| |
|---|----------|---------|---------------|---------------|-----------|
| 0 |  3.0 |  4.0 | 0.750 000 | 0.750 031 | 3.05 × 10⁻⁵ |
| 1 |  7.0 |  8.0 | 0.875 000 | 0.875 031 | 3.05 × 10⁻⁵ |
| 2 |  5.0 |  4.0 | 1.250 000 | 1.250 031 | 3.05 × 10⁻⁵ |
| 3 |  3.0 |  2.0 | 1.500 000 | 1.500 031 | 3.05 × 10⁻⁵ |
| 4 |  1.0 |  8.0 | 0.125 000 | 0.125 031 | 3.05 × 10⁻⁵ |
| 5 |  7.0 |  4.0 | 1.750 000 | 1.750 031 | 3.05 × 10⁻⁵ |
| 6 |  2.0 |  3.0 | 0.666 667 | 0.666 656 | 1.02 × 10⁻⁵ |
| 7 | 11.0 |  7.0 | 1.571 429 | 1.571 442 | 1.31 × 10⁻⁵ |

All eight divisions are fed into the pipeline on **consecutive clock cycles**,
demonstrating throughput = 1 result/cycle with latency = 17 cycles.

**Maximum absolute error:** 3.05 × 10⁻⁵ ≈ 2 × 2⁻¹⁶ (two Q16.16 LSBs)  
**Fixed-point resolution:** 1 LSB = 2⁻¹⁶ ≈ 1.53 × 10⁻⁵
